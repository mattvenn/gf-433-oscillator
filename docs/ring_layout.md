# Ring-core layout: generator, DRC/LVS/antenna, PEX vs schematic

The VCO ring core of `sim/vco/vco_bias.py` (default `P`, `rideal=0 lnw=4.5 lnp=100`). It has 5 stages, the master leg
with `MPB`, and the coarse switches. The const-gm reference and the filter are not in it. Brief:
`docs/handoff_ring_layout.md`. Everything here is regenerated by a rerun. There are no hand edits.

```
python3 layout/gen/ring_core.py          # -> layout/ring_core.gds (+ build/layout/*.mag, the magic cells)
python3 layout/gen/export_core.py        # -> layout/ref/ring_core.spice (LVS source, from vco_bias.netlist())
bash    layout/gen/check.sh              # magic DRC, KLayout DRC, antenna, LVS -> build/check/ring_core/summary.txt
bash    layout/gen/pex.sh lvs|c|rc       # -> layout/pex/ring_core_{lvs,c,rc}.spice (magic 8.3.642)
python3 layout/gen/pex_sim.py            # schematic vs extracted f and P -> build/pex_sim/results.txt
```

## Tool and why
**magic Tcl, generated from Python** (`layout/gen/ring_core.py` writes `build/layout/ring_core.tcl` and runs magic).
Instead of gencells, it paints raw magic layers (diffusion, poly, contacts, metal, wells) at coordinates that
the generator computes, on the 5 nm grid. Why:
- The repo's `mag/` flow, netgen LVS and PEX are magic-based, so the same tool draws, checks and extracts. There is no
  GDS layer-map or pcell-version step in between.
- Painting poly over diffusion gives `nfet_03v3`/`pfet_03v3` directly, so the generator knows every terminal
  position exactly. KLayout pcells would need the terminals read back from pcell geometry, and the KLayout pcells
  in this image are a separate Python stack.
- The stages are real magic subcells (`ring_stage` ×5, `ring_master`, `ring_sw`) placed with the same
  orientation. The wiring, wells, guard rings and rails are in the top cell `ring_core`.

The sizes come from `vco_bias.P`. `--set k=v` takes the same parameter names, and `--rows` sets the foot folding
(layout only). No device size was changed. The narrowest devices (foot legs, W = 0.25 µm) are drawn as dogbone
fingers. The channel is 0.25 µm wide, and the S/D pads widen to 0.38 µm for the contacts, 0.11 µm clear of the gate. So
there was no DRC-minimum problem to report.

Tool versions: magic 8.3.684 (generate, DRC, LVS extraction, antenna), **magic 8.3.642 for PEX**. 8.3.684 drops
node-to-substrate C (`~/.local/magic642`). netgen 1.5.323, KLayout 0.30.12 with the PDK `gf180mcu.drc`
(variant D), ngspice-47, PDK `/foss/pdks/gf180mcuD`.

## Floorplan
One row of 7 columns, all in the same orientation (R0). The image is `docs/img/ring_core.png`
(`tools/render_gds.py`, default KLayout colours).

```
 col:   0        1        2        3        4        5          6
      stage0   stage4   stage1   stage3   stage2   master     switches (5 bit slices)
 ┌────────────────────────────────────────────────────────────────────────────┐ p+ substrate tap ring (VSS)
 │ VDD rail M1+M2 2.4 µm (over the n-well tap ring's top side)                │
 │ ┌ n-well + n-well tap ring ─────────────────────────────────────────────┐  │
 │ │ head-gate band: vbp M3 track ─────────────────────────────┐           │  │
 │ │  P(5/0.28) H(6/1)  P H    P H    P H    P H     MPB 12×(1/1)  TP0..4  │  │
 │ └───────────────────────────────────────────────────────────────────────┘  │
 │ ring channel: S a0 S a1 S a2 S a3 S a4 S   (M2; S = VSS shield)            │
 │   N(2/0.28) in each stage; in/out M1 risers cross the channel at 90°       │
 │ foot: 7 rows of W=0.25 fingers (k=16 base, 16/8/4/2/1 coarse, fine L=4)    │  TN0..4, TD0..4
 │   gate bands: M3 bias tracks vbn, g4..g0, vctrl (run to the switch column) │
 │ VSS rail M1+M2 2.4 µm (over the p+ ring's bottom side)                     │  bit/bitb pins (M3, bottom)
 └────────────────────────────────────────────────────────────────────────────┘
   a0 output: M2, left edge     vbn, vctrl: M3, right edge
```

**Stage cell** (`ring_stage`, 18.5 µm pitch). From the bottom:
- The foot rows. Each row is a shared diffusion with alternating VSS/f S/D pads (VSS via1 row at the bottom, f at the top),
  with a p+ tap at the left end of every row under the VSS M2 spine, and an f M1 spine on the right.
- Gate groups: an M1 strap over the poly contacts, then via1+via2 up to that net's M3 track in the band above the row.
- The inverter NMOS. Its source is the f spine.
- The ring channel.
- The PMOS row inside the n-well: P (5/0.28) next to the head H (6/1). Their shared node h is an M1 bridge.
- H's gate goes to the vbp M3 track, and H's source goes up into the VDD rail.

The input is a poly contact below and one above the channel, joined by an M1 riser placed 1.2 µm clear of the output
riser. The output riser is the drain M1 from N up to P.

**Loop folding:** the column order is 0, 4, 1, 3, 2, so every stage-to-stage wire spans at most 2 columns. Each ring
track is padded to exactly the same length (38.66 µm, from the generator's own length report). a0's padding runs out
to the left edge as the output pin. a1…a4 have labels on their tracks and can be reached from M3 for a later buffer or
probing. Every ring track sits between two VSS shield tracks (0.7 µm gaps), so each node has the same neighbours and
no ring node runs alongside another one.

**Wiring classes:**
- **Ring nodes:** M2 tracks in the channel, plus M1 risers inside the cells.
- **Bias nets (vbn, vctrl, g0…g4, vbp):** M3 only, in the foot gate bands and the head band. They never enter the ring
  channel, so no bias net crosses a ring node at all. The only things that cross the ring tracks are the cells' own
  vertical M1 risers, at 90°.
- **Supplies and taps:**
  - VDD/VSS are 2.4 µm M1+M2 rails with via1 arrays every 2 µm.
  - Each foot-row tap has a via1 array (about 10 cuts).
  - There is an n-well tap ring around the whole PMOS group, and a p+ substrate ring around the core. Its bottom side
    is under the VSS rail.
  - **Metal4 and Metal5 are not used.**

Implementation detail found the hard way: magic `load` opens an existing `.mag`, so the generator now deletes the old
cells before painting. Otherwise a rerun paints on top of the previous run's geometry.

## Area
Bounding box **147.91 × 48.62 µm** (7192 µm²), including both guard rings and the pin stubs. Column pitch 18.52 µm.

## Checks
All are judged from the output files, in `build/check/ring_core/summary.txt` (logs in the same directory). A full
`check.sh` takes about 10 s.

| Check | Result | Log |
|---|---|---|
| magic DRC, `drc(full)`, from the GDS | **0** | `build/check/ring_core/magic_drc.txt` |
| KLayout DRC, gf180mcu.drc variant D, `decks=all,-density` (176 decks run) | **0** | `build/check/ring_core/klayout_drc.lyrdb`, `klayout_drc.log` |
| KLayout density deck alone | 8: M1.4–M5.4, MT.3, PL.8, DCF.1b. Whole-die coverage minimums, met by tile/chip fill, not a block property | `build/check/density/` |
| magic antenna (flattened copy, fresh session, `antennacheck debug`) | **0 violations** | `build/check/ring_core/antenna.txt` |
| antenna mutation: an M3 comb (20 × 25 µm fingers) on the bit0 pin, i.e. the 2/0.28 TN0 gate | **caught**: magic "ratio 1033.67 > limit 400"; KLayout ANT.16_i_ANT.4 ×2 | `build/mut/antenna/check/summary.txt` |
| LVS, netgen, source = `layout/ref/ring_core.spice` from `vco_bias.netlist()` | **"Circuits match uniquely", no property errors**: 73 devices (303 nfet / 27 pfet fingers merged in parallel), 35 nets, 19 pins | `build/check/ring_core/lvs.report` |
| LVS mutation: bit-0 and bit-1 coarse legs swap gate nets (`--mutate swapbits`) | **fails**: "Top level cell failed pin matching". netgen can only match it with bit0/bit1 exchanged | `build/mut/swapbits/check/lvs.report` |

`check.sh` passes LVS only if the final result is "Circuits match uniquely" *and* there is no "property errors" or "do
not match" anywhere in the report. Two traps got caught along the way:
- `decks=-density` on its own makes the KLayout deck run **0** decks and report 0. `check.sh` now prints the deck count.
- A flat 600 µm² plate did *not* trip the antenna check. gf180's metal antenna rules are sidewall ratios, so the
  deliberate violation has to be a long thin comb.

## Capacitance per ring node
Extracted with magic 8.3.642, C only (`cthresh 0`, coupling included, substrate tied to VSS). Values are node totals
in fF, from `layout/pex/ring_core_c.spice`. Diffusion area/perimeter C is in the device models (ad/as/pd/ps), not here.

| node | total | to VSS | to VDD | to other ring nodes | other |
|---|---|---|---|---|---|
| a0 | 10.23 | 7.25 | 0.78 | a1 0.65, a4 0.56 | 0.98 |
| a1 | 10.08 | 6.94 | 0.78 | a0 0.65, a2 0.61, a3 0.04, a4 0.09 | 0.96 |
| a2 | 10.06 | 6.96 | 0.78 | a1 0.61, a3 0.65, a4 0.09 | 0.97 |
| a3 | 9.99 | 6.97 | 0.80 | a1 0.04, a2 0.65, a4 0.57 | 0.97 |
| a4 | 10.07 | 6.95 | 0.85 | a0 0.56, a1 0.09, a2 0.09, a3 0.57 | 0.96 |

The nodes match to ±1.2% (9.99–10.23 fF). **The schematic's `cw = 2 fF` is about 5× too low:** the wiring is about
10 fF per node. The coupling to the neighbouring ring nodes is the stage's own input-to-output (a_i → a_i+1) coupling
inside the cell. Its Miller effect counts double.

How the layout got there (all with C extraction):
1. A 4-row foot gave 57 µm wires. A 7-row foot gave 38 µm.
2. Without shields the nodes were 8.2–10.2 fF (±11%), with up to 4.1 fF between adjacent tracks.
3. Shields gave 12.5 fF ±1%.
4. Moving the input riser 1.2 µm clear of the output riser gave 10.1 fF ±1%.

The shield gap (0.4–1.5 µm) hardly changed the total, because the C is mostly M2/M1 area over the substrate.

## PEX vs schematic (tt, 27 °C, VDD 3.3 V, vctrl 1.65 V)
`layout/gen/pex_sim.py` builds each deck from `vco_bias.deck()`:
- **ref**: the deck unchanged, with the const-gm reference and the schematic core at cw = 2 fF. It gives vbn.
- **Every other variant**: the reference is replaced by an ideal vbn source at that value, and the core lines are
  replaced by `Xcore … ring_core`.
- **sch**: the schematic core with cw = 2 fF.
- **sch0**: the schematic core without cw.
- **lvs / c / rc**: the extracted core, swapped in for the schematic subckt the way `tools/pexswap.py` does it.
  pexswap itself is hard-wired to `layout/pex/<block>.spice` with a build/-relative include, so the swap is inlined
  with an absolute include.

`ref` power includes the reference. All other powers are the core only.

Results are from `build/pex_sim/results.txt` (2026-11-07 22:45). vbn = 1.1989 V from the reference. Every run is
settled: f over rises 1–6 and 6–11 agrees to < 0.05%. No run reported "Transient op", singular matrix or timestep
errors.

| code | ref f / P | **sch** (cw 2 fF) f / P | sch0 (no cw) f | **c** f / P | **rc** f / P | **rc vs sch** f / P |
|---|---|---|---|---|---|---|
| 0  | 241.5 MHz / 0.983 mW | 241.7 MHz / 0.745 mW | 309.7 MHz | 177.2 MHz / 0.745 mW | 152.0 MHz / 0.723 mW | **−37.1 % / −2.9 %** |
| 10 | 416.5 / 1.377 | 416.7 / 1.139 | 531.2 | 281.6 / 1.110 | 244.7 / 1.086 | **−41.3 % / −4.7 %** |
| 31 | 697.9 / 2.043 | 698.3 / 1.805 | 840.9 | 455.0 / 1.749 | 401.6 / 1.723 | **−42.5 % / −4.6 %** |

C-only vs sch: −26.7 / −32.4 / −34.8 % in f. The extra R (`extresist`) costs another 10–12 % on top of that.
`ref` and `sch` agree to 0.07 %, which confirms that the ideal vbn source replaces the reference faithfully.

**The shift is far outside the expected ~10 %**. Per the brief, that means the 2 fF wiring estimate was wrong, and the
extraction says by how much: about 10 fF of wiring per node (table above), so about 5× the estimate. Power drops only
3–5 %, because the starved stages set the current, so the f/P figure of merit falls by about 40 %. To recover
433 MHz, the tuning map has to move up. At vctrl 1.65 V, code 31 gives 402 MHz extracted. For the sims agent: use
`cw ≈ 10 fF` and add R (or simulate with `layout/pex/ring_core_rc.spice`).

The `lvs` (connectivity-only) variant checks the swap:
- At code 31 it gives 891 MHz, 6 % above sch0. This is the junction geometry (open issues).
- With the schematic's ad/pd formula substituted it reproduces sch0 exactly at all three codes: 309.70 / 531.24 /
  840.89 MHz (`build/diag/`).
- With the layout's smaller drain junctions and *no* wiring C at all, the netlist locks into a higher ring mode at codes
  0 and 10 (895 / 648 MHz, both stable). It's an artifact of a netlist with no wiring C, and the C and RC netlists run
  in the fundamental mode. It's still a reminder to check ring start-up and mode, for example from random initial
  states, at the weakest code.

## Run times
- Generator: about 1 s (magic paints and writes the GDS).
- `check.sh`: magic DRC 1 s, antenna 1 s, KLayout DRC 6 s, LVS < 1 s.
- `pex.sh`: under 1 s per mode.
- `pex_sim.py`: 80 s wall for all 18 runs, 8 parallel single-thread ngspice processes. Per run: ref/sch about 5–8 s, lvs about 25 s, c about 23 s, rc about 52 s.

## Open issues
- **Wiring C is about 10 fF per node, not 2 fF.** The sims agent should rerun the tuning map with `cw ≈ 10e-15`, or
  with this extraction, before the code-to-frequency plan is fixed. Shorter wires need a narrower column. The foot (48
  fingers of 0.25/1 plus the 0.25/4 fine leg) sets the column width.
- The schematic's `ad = as = 0.5·W`, `pd = ps = 2(W + 0.5)` overestimates the inverter drain junctions. The drains are
  shared S/D pads here. That alone makes the extracted core about 6% faster than `sch0` (verified: with the schematic's
  ad/pd formula put into the `lvs` extraction, the result equals `sch0` to 0.01%).
- Ring-mode robustness: the no-wiring-C netlist falls into a higher-order mode at low codes from the deck's `.ic`.
  The extracted C/RC netlists don't. A start-up/mode check across corners at code 0 belongs in the sims plan.
- Substrate coupling isn't modelled (substrate tied to VSS). The p+ ring and n-well ring are the protection.
- Not placed in the TT tile yet, as the brief says. The pins are at the core edges (a0 on the left on M2, vbn/vctrl on
  the right on M3, bit/bitb at the bottom on M3), so the tile router can reach them. Metal4 is free for the power
  stripes. The core is 148 µm wide, which fits a 1×2 tile's width.
- The KLayout density rules (whole-die coverage) are left to TT's fill.
- The extractions in `layout/pex/` are stamped with the magic version and date. `pex_sim.py` refuses an extraction
  older than the GDS.
